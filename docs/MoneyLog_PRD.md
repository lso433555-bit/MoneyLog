# MoneyLog PRD

## 1. 개요

**배경**: 부부(성완·예은)가 매달 수입 대비 지출이 어디로 나가는지 파악하기 어려움. 고정지출/유동지출이 뒤섞여서 다음달 어디를 아껴야 할지 감이 안 옴.

**목적**: 아이폰/아이패드/노트북/데스크탑에서 모두 쓸 수 있는 부부 공용 가계부 웹앱을 만들어, 수입 대비 지출 흐름과 고정/유동지출 구조를 눈에 보이게 만든다.

**사용자**: 성완, 예은 두 명. 같은 household(가구) 아래 데이터를 공유하며 함께 기록한다.

---

## 2. 목표 / 비목표

**목표**
- 지출을 빠르게 입력하고, 이번 달 예산 대비 상황을 한눈에 확인한다
- 고정지출과 유동지출을 구분해서 관리한다
- 전월 대비 지출 변화를 보고 다음달 절약 포인트를 찾는다
- 대출 상환/적금 진행 상황도 함께 확인한다

**비목표 (이번 버전에서 하지 않는 것)**
- **은행/카드 자동 연동을 하지 않는다.** 정식 오픈뱅킹 API는 개인사업자 자격과 큰 초기 비용(보안점검 포함 수백~수천만원대)이 필요해 배제. CODEF 같은 민간 연동도 건당 과금과 계좌 인증정보 위탁 부담이 있어 배제. → **수동 입력**으로 진행하며, 카드 문자 알림 복사-붙여넣기 파싱 정도만 보조로 고려 가능.
- **푸시 알림을 넣지 않는다.** 예산 초과는 앱을 열었을 때 대시보드 색 변화로만 안내한다.
- **거래 자동 카테고리 추천(AI)은 넣지 않는다.** 데이터가 쌓인 이후 필요하면 추가 검토.

---

## 3. 화면 구조 (정보 구조)

5개 탭 — 모바일은 하단 탭바, 데스크탑은 좌측 사이드바로 반응형 전환.

1. **홈 (대시보드)**
2. **입력** (지출/수입 등록)
3. **리포트**
4. **고정지출**
5. **설정** (카테고리 관리, 예산 설정, 계정 정보)

---

## 4. 기능 요구사항

### 4.1 홈 (대시보드)
- 이번 달 남은 예산을 큰 숫자로 표시 (수입 − 지출)
- 수입/지출 요약 2칸 카드
- 고정지출 목록 (아이콘 + 이름 + 금액)
- 유동지출 최근 내역
- 대출/적금 진행률 바 카드 (섹션 4.7 참고)
- 카테고리별 예산 대비 지출 상태를 색으로 표시 (섹션 4.5 참고)
- 디자인: "디지털 통장" 컨셉 — 절취선으로 섹션 구분, 금액은 고정폭(tabular) 폰트로 표기해 통장에 찍힌 숫자 같은 느낌

### 4.2 입력 (지출/수입 등록)
- 모달 방식으로 열림 — 페이지 이동 없이 등록 후 대시보드로 즉시 반영
- 입력 항목: 수입/지출 토글, 금액, 카테고리, **고정/유동 토글**, 메모, 날짜(기본값 오늘), 결제수단(선택)
- **중요**: 고정/유동은 카테고리와 별개의 독립된 속성이다. 카테고리 자체에 고정성 여부를 고정하지 않는다 — 예를 들어 "헌금" 카테고리는 십일조/월정헌금처럼 고정으로 등록할 수도 있고, 감사헌금처럼 유동으로 등록할 수도 있다. "보험"도 대부분 고정이지만 추가 가입 시 유동으로 등록 가능해야 한다.
- 최근 사용한 카테고리를 상단에 우선 노출해 빠른 입력 지원 (목표: 건당 10~15초 이내)

### 4.3 고정지출 관리
- `recurring_templates` 목록 표시 (이름, 카테고리, 금액, 매달 며칠에 반영되는지)
- 추가 / 수정 / 해지(활성 여부 토글) 가능
- **자동 생성 로직**: 앱 진입 시, 이번 달에 아직 생성되지 않은 활성 템플릿이 있으면 자동으로 `transactions`에 생성한다 (별도 서버 배치job 없이, 앱 로드 시점에 확인하는 방식)
- **수입도 동일한 방식으로 등록한다.** 월급처럼 매달 고정 수입은 `recurring_templates`에 income 타입으로 등록하고, 나중에 금액이 오르면 템플릿을 직접 수정한다 (자동 인상 로직 없음)

### 4.4 리포트
- 상단에 월 선택 (좌우 화살표로 이전/다음 달 이동)
- 이번 달 vs 지난달 총지출 비교 — 증감 %와 화살표 아이콘(늘었으면 빨강, 줄었으면 초록)
- 카테고리별 지출 막대그래프 (금액 큰 순 정렬)
- "지난달 대비 많이 늘어난 카테고리 top 3"를 텍스트로 짚어줌
- 고정 vs 유동 지출 비율 (도넛차트 또는 막대)

### 4.5 예산 알림 (설정 + 대시보드)
- 설정 탭에서 카테고리별 월 예산 입력
- 대시보드 카테고리 카드에서:
  - 지출이 예산의 80% 이상 → 경고색(앰버)
  - 100% 이상 → 초과 표시(레드 텍스트)
- 푸시 알림/팝업 없음, 앱을 열었을 때 자연스럽게 보이는 정도로만

### 4.6 카테고리 관리 (설정)
- 기본 제공 13개 카테고리 (섹션 6 참고)
- 커스텀 카테고리 추가 가능하도록 구조는 열어두되, 초기 화면에 커스텀 추가 UI를 꼭 넣을 필요는 없음 (스키마 차원에서 확장 가능하게만)

### 4.7 자산 현황 (대출/적금)
- 대시보드 하단에 진행률 바 카드로 표시
- 항목: 이름, 종류(대출/적금), 목표금액, 현재잔액, 월납입액
- **잔액은 자동 계산하지 않고 수동으로 갱신**한다 (은행 연동 없음과 같은 이유)

### 4.8 로그인
- Google OAuth
- 두 사람의 이메일만 화이트리스트로 로그인 허용 (그 외 이메일은 접근 거부)
- 로그인 성공 시 두 사람이 자동으로 하나의 household로 묶임 (household가 없으면 최초 로그인 시 자동 생성)

## 5. 데이터 모델

| 테이블 | 필드 | 비고 |
|---|---|---|
| `households` | id, name, created_at | |
| `household_members` | id, household_id, user_id, display_name | Supabase Auth user와 연결 |
| `categories` | id, household_id(nullable), name, icon, color, sort_order | household_id가 null이면 기본 카테고리, 값이 있으면 커스텀 |
| `transactions` | id, household_id, user_id, type(income/expense), category_id(nullable), amount, is_fixed, memo, date, payment_method(nullable), recurring_template_id(nullable) | 지출/수입 통합 테이블 |
| `recurring_templates` | id, household_id, category_id, type(income/expense), name, amount, day_of_month, is_active | 고정지출/고정수입 자동 반복용 |
| `budgets` | id, household_id, category_id, month, amount_limit | |
| `assets` | id, household_id, name, type(loan/savings), target_amount, current_amount, monthly_amount, updated_at | 대출/적금, 수동 갱신 |

RLS(Row Level Security): household_members에 속한 사용자만 해당 household 데이터를 읽고 쓸 수 있음.

## 7. 디자인 시스템

**컨셉**: "디지털 통장" — 옛 은행 통장의 도트프린터 숫자, 절취선, 도장 찍힌 항목 느낌을 현대적으로 재해석.

- 큰 금액 숫자: 고정폭(tabular/monospace) 폰트로, 통장에 찍힌 숫자 같은 리듬감
- 섹션 구분: 통장 절취선처럼 점선 구분선 사용 (과한 장식 없이 점선만)
- 카테고리: 원형 아이콘 배지, 카테고리마다 고정된 색 (섹션 6 참고)
- 전체 톤: 미니멀하고 절제됨 — 통장 모티프는 숫자 표시부와 구분선에만 집중하고, 입력 폼/버튼/차트 등 나머지 요소는 모던하고 깔끔하게 유지 (한 군데에만 힘주고 나머진 절제)

## 8. 기술 스택

- Next.js (App Router) + TypeScript
- Tailwind CSS
- Supabase (Auth, Database, RLS)
- Vercel 배포
- next-pwa (아이폰/아이패드 홈 화면 추가 지원)

**비용**: 위 스택 전부 개인/소규모 프로젝트 기준 무료 플랜으로 충분. 단, Supabase 무료 플랜은 7일간 DB 활동이 없으면 프로젝트가 일시 중지되므로 며칠에 한 번은 앱을 열어야 함.
